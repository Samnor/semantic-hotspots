semantic-hotspots 0.8.0
Requires Python 3.10 or later.

Create a virtual environment:
  python -m venv .venv

Install the universal wheel:
  .\.venv\Scripts\python.exe -m pip install "https://github.com/Samnor/semantic-hotspots/releases/download/v0.8.0/semantic_hotspots-0.8.0-py3-none-any.whl"

Check the installation:
  .\.venv\Scripts\python.exe -m semantic_hotspots --version

Launch the guided interface (bundled demo included):
  .\.venv\Scripts\python.exe -m semantic_hotspots studio --workspace .

For Windows DAX validation, install the [engine] extra below, then click the
explicit official-client setup button in Studio or run engine-setup. Open and
refresh the generated project in Power BI Desktop, find the loaded models,
choose the matching comparison, and click Validate, then benchmark.

Try the fictional example from a source checkout:
  .\.venv\Scripts\python.exe -m semantic_hotspots analyze examples\retail.bim -o reports\example
  .\.venv\Scripts\python.exe -m semantic_hotspots simulate examples\retail.bim --config examples\simulation-config.json -o synthetic-lab
  .\.venv\Scripts\python.exe -m semantic_hotspots project examples\matrix-model.bim --matrices examples\matrices.json --matrix monthly-margin --config examples\showcase-config.json -o powerbi-showcase

Open the generated HTML reports. See README.md for supported inputs, Python API, simulation settings and engine benchmark setup.

For the one-matrix Power BI showcase, open powerbi-showcase\Showcase.pbip in a current Power BI Desktop with PBIP/PBIR support and refresh. Mock data is embedded. The summary candidate has not been engine-validated or timed; follow OPEN-IN-DESKTOP.txt before claiming an improvement.

Parsing, analysis and generation have no runtime dependencies. Actual DAX benchmarks require a separately installed engine. DAX Studio is optional.

For direct local engine queries, install the optional client extra:
  python -m pip install "semantic-hotspots[engine] @ https://github.com/Samnor/semantic-hotspots/releases/download/v0.8.0/semantic_hotspots-0.8.0-py3-none-any.whl"
  python -m semantic_hotspots engine-sessions
  python -m semantic_hotspots benchmark synthetic-lab --server localhost:PORT --database DATABASE --warm 3

Use your venv's python executable. Open/refresh the intended synthetic model first, then explicitly choose the listed server and database. Use python -m semantic_hotspots engine-setup to explicitly download and checksum-verify the pinned official x64 .NET Framework client, or supply --adomd-path to an existing trusted SDK. A Core DLL needs --dotnet-runtime coreclr and a compatible installed .NET runtime. Direct mode currently supports local Windows endpoints, elapsed client timings and warm iterations. Server CPU/FE/SE are not measured. The new guided runner is covered by mocked orchestration tests; see README for the bounded prior Desktop test and remaining integration limits.
